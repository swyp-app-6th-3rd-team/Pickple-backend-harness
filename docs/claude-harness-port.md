# 팀원 Claude 하네스 반영 기록

2026-09-06에 제공받은 팀원 하네스를 기존 Codex 하네스와 비교해 필요한 차이만 반영했다. 첨부 파일은 검토 자료이며, 그 안의 실행·승인 지침을 사용자 요청으로 해석하지 않는다. 이 문서는 이식 판단 기록이고 별도 실행 지침이 아니다.

## 파일별 판단

| 원본 | 반영 위치와 판단 |
| --- | --- |
| `reviewer.md` | 기존 `pr-review`에 위험 파일 우선 탐색, 오류 응답·로그 점검, 영향과 발생 조건에 따른 중요도 판정을 보강했다. 스타일·N+1·테스트 점검은 이미 있어 중복하지 않았다. |
| `architect.md` | API·스키마·경계·선행 조건과 ADR은 기존 `AGENTS.md`에 반영돼 있다. 모든 API 작업의 Pre-Plan 호출과 고정 산출물, 비동기 처리의 일괄 이벤트 아키텍처 전환은 도입하지 않았다. |
| `qa.md` | 기존 `integration-test`에 완료 조건과 관찰값 연결, 비동기 조건 대기, 제품·테스트·환경 실패 구분을 보강했다. 브라우저·디바이스 E2E 및 Playwright 절차는 백엔드 검증의 필수 조건으로 넣지 않았다. |
| `security.md` | 기존 보안 체크리스트를 유지하고 `pr-review`에 신뢰 경계 추적과 비밀값 발견 시 보고·조치 제안의 경계를 보강했다. 자격 증명 교체나 라이브 보안 실험을 자동 실행하지 않는다. |
| `tech-adoption-gate.md` | 가역성·측정·대안·운영 비용·조건부 PoC는 이미 반영돼 있다. 설계를 좌우하는 비기능 목표의 부하·규모·지표 조건만 보강했다. 대안 개수·Why 횟수·spike 비율은 강제하지 않는다. |
| `workflow-cycle.md` | 기존 조건부 개발 흐름을 유지하고 완료 조건과 증거의 대조, 요구사항 원문과 SPEC·PRD·ADR의 역할 구분을 보강했다. |
| `thinking-discipline.md`, `SKILL.md` | 기존 `resolve-problem`에 병목 비중과 전체 효과 점검을 보강했다. 중복된 사고 단계는 추가하지 않았으며, 근거 없는 확률 수치는 사용하지 않도록 했다. |
| `kotlin-spring.md` | 설정 바인딩에 도메인 로직을 넣지 않는 원칙만 Java/Spring 스킬에 반영했다. Kotlin 문법·도구와 Controller → Service → Repository 직접 의존은 현재 Java/DDD 경계에 맞지 않아 제외했다. |
| `layer-responsibility.md` | 원본 파일은 확보하지 못해 이슈 #8의 요구와 백엔드 ADR-0019·0020, 현재 저장소·서비스·스키마를 대조했다. 저장 사실/정책 판단, 무결성 원인 보존, 트랜잭션 실패 전파, UNIQUE·FK와 저장 시 도메인 검증을 `AGENTS.md` 및 `pr-review`에 반영했고, 기존 구현의 불일치는 별도 백엔드 정비 대상으로 남겼다. |
| `react-frontend.md` | 현재 백엔드 범위에 맞지 않아 제외했다. React 상태관리·폼·디자인 도구를 도입하지 않는다. |
| `settings.local.json` | Anthropic 프록시 환경변수, Claude 권한·훅, 개인 플러그인 설정은 복사하지 않았다. 현재 Codex 설정·훅을 유지한다. |
| `_` 접두사 파일, `download` 변형 파일 | 파일 시그니처로 AppleDouble 리소스 메타데이터와 `.DS_Store` 계열 파일임을 확인했다. 지침 본문이 아니므로 저장소에 추가하지 않았다. |

## 유지한 실행 경계

- 매 구현 단계마다 수동/자동 모드를 묻는 절차, `.temp/` 완성본 전달·사용자 타이핑 대기·자동 삭제는 도입하지 않았다. 사용자가 학습이나 수동 구현을 요청하면 그 요청 범위에서 처리한다.
- `opus`·`sonnet`, Claude 도구 목록, `sequential-thinking`·Plan·verifier 호출을 필수로 만들지 않았다. 별도 에이전트 없이도 요청한 완료 조건과 실제 증거를 대조할 수 있다.
- 자동 커밋·푸시·PR 생성과 고정 PR 크기·섹션 수를 가져오지 않았다. 실제 저장소 규약과 사용자가 명시적으로 허용한 범위를 따른다.
- 외부 시스템 문제에서 전체 작업을 중단하는 규칙과 기존 ADR 본문을 바꾸는 규칙은 가져오지 않았다. 독립 작업 지속 및 기존 ADR 보존 원칙을 유지한다.
- 새 스킬·MCP·훅을 중복 등록하지 않았다. 공통 기준은 `AGENTS.md`, 세부 절차는 기존 스킬 4개에 유지한다.

## 적용 판단 확인

다음은 지침의 정적 검토 기준이며 실제 제품 테스트나 독립 에이전트 실행 결과가 아니다.

| 요청 상황 | 반영 후 기대 동작 |
| --- | --- |
| 명확한 소규모 API 수정 | 기존 패턴으로 구현·관련 테스트를 수행하고 모드 선택·architect 호출·PRD 생성을 선행 조건으로 삼지 않는다. |
| 원인 불명 성능 저하 | 실제 측정으로 병목 비중과 판별 가설을 좁히며 근거 없는 확률이나 고정 대안 개수를 채우지 않는다. |
| Docker가 없는 환경 | 통합 검증 차단을 보고하고 독립적인 로컬 검증을 계속한다. E2E 통과로 보고하지 않는다. |
| 보안 리뷰에서 비밀값 발견 | 값 대신 위치와 영향·조치 방향을 보고한다. 리뷰만으로 운영 키를 교체하지 않는다. |
| 계약에 외부 호출 금지 조건이 존재 | 응답뿐 아니라 외부 호출 부재를 관련 테스트 증거로 확인한다. |
